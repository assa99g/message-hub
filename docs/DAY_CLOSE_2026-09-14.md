## 2. Что создаём

Message Hub — личная локальная программа на Mac с веб-интерфейсом. Собирает новую входящую текстовую информацию из нескольких источников, сохраняет её и в дальнейшем с помощью ИИ выделяет темы, важность, задачи и сроки. Пользователь рассматривает и утверждает предложения до изменения календаря.

Полный желаемый охват: Telegram и WhatsApp (каналы и личные сообщения), несколько почтовых ящиков, RSS, ВКонтакте, названия и описания YouTube. Обрабатывается только текст; без вложений, изображений, голоса, видео и расшифровок YouTube. Возможность каждого подключения проверяется отдельно.

Работа пока на одном компьютере; нужно предусмотреть перенос на другой Mac. Разработка и повседневное использование могут идти под разными пользователями macOS. Рабочие данные должны переживать обновления, принадлежать рабочему пользователю и быть отделены от тестовых. Автозапуск при входе требуется, но ещё не реализован.

## 3. Решения и предпочтения

- Пользователь принял существующие семь экранов за отправную точку; корректировать их можно позже. Не начинать заново проектирование и длинный опрос по настройкам.
- Два приоритетных источника — Gmail и Telegram. Первым выбран Gmail, сразу несколько ящиков.
- Один Google Cloud проект и один OAuth-клиент приложения обслуживают несколько ящиков. Каждый ящик отдельно авторизуется пользователем. В Testing все адреса нужно добавить в Test users. Дополнительные адреса ещё не определены.
- Пользователь хочет собирать, хранить и анализировать статистику. Для локальной версии выбрана и реализована основа SQLite. Сохранять историю событий, а не только текущие состояния. Набор расширенных отчётов и числовых показателей из писем пока не согласован.
- Первое подключение: только новые сообщения с момента подключения, без старой переписки. Позиция и дата начала отдельные для каждого ящика.
- Сбор по умолчанию раз в час, интервал настраиваемый. Во время сна или остановки — пауза; затем догрузка в пределах возможностей источника.
- Простое открытие материала в Message Hub считается интересом. После месяца без наблюдаемого взаимодействия предлагать пересмотреть источник. Отсутствие данных о чтении в исходном сервисе не доказывает отсутствие интереса. Автоматические удаления и отписки не согласованы.
- Группы: срочное, важное, обычное. Срочность и важность независимы, важность 1–5; срок в ближайшие 24 часа — предлагаемый порог срочности. Пользователь может исправлять классификацию, настраивать группы, сферы и приоритет отправителей.
- Сферы: работа; дом и быт; семья и личное; здоровье; финансы; развитие и обучение; отдых и увлечения. Возможны несколько сфер у материала.
- Повторное поручение объединяется в одну задачу со ссылками на все сообщения. Неясное поручение требует уточнения. Изменение срока утверждённой задачи предлагается пользователю.
- Основной календарь — Google Calendar, отдельный «План задач»; Apple Calendar — интерфейс календаря Google. Занятость iCloud подключается отдельно. График работы: Пн–Чт 08:00–15:00, Пт 08:00–14:00, Europe/Madrid. Рабочие и личные задачи планируются совместно.
- ИИ и запись в календарь ещё не подключены. Предложения раздела 11 PROJECT_CONTEXT.md нельзя считать отдельными подтверждениями всех деталей пользователем. Перед реальной передачей текстов ИИ определить поставщика и объём передаваемых данных.

## 4. Что подготовлено

- `message_hub/store.py`: SQLite — аккаунты, сообщения, события сбора и открытия, счётчики, защита от дублей по аккаунту и идентификатору письма.
- `message_hub/gmail.py`: read-only Gmail API, разбор текстовых частей и HTML без загрузки вложений, история изменений и восстановление после её истечения, отдельные разрешения в Связке ключей macOS.
- `message_hub/server.py`: локальный сервер, настройки OAuth-клиента, вход в системном браузере, сбор нескольких ящиков, общий интервал, защита API ключом локальной сессии и проверкой Host.
- `prototype/dist/live.html`, `live.js`: рабочие страницы Gmail на основе прежних стилей и навигации. Источники, общий список с фильтром по ящику, просмотр текста, счётчики. Остальные разделы явно обозначены как ещё не подключённые.
- Прежние `prototype/dist/index.html`, `app.js`, `styles.css`: отдельный демонстрационный прототип на вымышленных данных, сохранён как основа экранов. Его календарь и задачи не являются реальными.
- `tests/test_gmail.py`, `tests/test_server.py`: 12 проверок на вымышленных данных.
- `requirements.txt`: зависимости подключения Google и macOS Keychain.
- `docs/GMAIL_SETUP.md`: запуск, настройка Google, поведение сбора и ограничения.
- `docs/DAY_3_2026-09-11.md`: решения дня 3; `docs/GOOGLE_CLOUD_STATUS.md`: подтверждённые данные проекта Google.
- `PROJECT_CONTEXT.md`: полный контекст; `README.md`: актуальные входные ссылки.

## 5. Проверки и фактические границы

В ходе разработки успешно пройдены 12 тестов: граница первого сбора, дубли и несколько ящиков, повторная авторизация, пагинация и истёкшая история, отказ без потери позиции, удалённые письма, извлечение текста без вложений, история открытий, независимость ошибок ящиков, настройки OAuth и защита локального сервера. Проверены зависимости, формирование OAuth PKCE S256, импорт macOS Keychain и отсутствие ошибок пробелов Git. Перед закрытием тесты повторяются.

В браузере проверены оформление подключения и пустой список писем. Реальный OAuth-вход, сохранение настоящего разрешения в Keychain и сбор почты пользователя **ещё не проверены**.

Не реализованы: ИИ-анализ, реальные задачи и календарь, расширенная аналитика, автозапуск, установщик, автоматические резервные копии, экспорт/восстановление и перенос через интерфейс. SQLite сама по себе не зашифрована. Не обещать эти возможности как работающие.

Текущий сбор исключает отправленные и черновики, включает доступные новые входящие, архив, спам и корзину. Окончательно удалённое до сбора письмо недоступно. Письмо с импортированной старой внутренней датой не считается новым. При недоступном встроенном тексте показывается пояснение. Открытие в Message Hub не меняет статус прочтения Gmail.

В Google External/Testing разрешение Gmail с refresh token действует 7 дней, затем потребуется повторный вход. Перед постоянной эксплуатацией отдельно завершить настройку статуса приложения с учётом требований Google. Корпоративные ящики могут иметь дополнительные ограничения администратора.

## 6. Локальное окружение и данные

Создано `.venv` с Python 3.12. Системный Python 3.9/LibreSSL оказался устаревшим для библиотек Google и заменён в окружении проекта. На другом компьютере нужно заново создать окружение, а не копировать `.venv`.

Запуск из корня репозитория, для разработки:

```sh
.venv/bin/python -m message_hub.server --data-dir .local-data
```

Программа открывает браузер и выводит новую ссылку локальной сессии. Обычно порт 8766. Ссылки и ключи прежней сессии не переносить в новый чат; после перезапуска использовать новую. Если старый сервер ещё работает, сначала проверить его, не запускать второй на том же порту. Во время разработки сервер запускался вручную, его работа в будущей сессии не гарантируется.

Без `--data-dir` данные находятся в `~/Library/Application Support/Message Hub` текущего пользователя macOS. OAuth-клиент сохраняется в подкаталоге `secrets`; разрешения аккаунтов — в Связке ключей. Каталог данных определяет отдельное пространство аккаунтов и ключей. `.local-data`, `.venv`, базы, секреты и токены исключены из Git.

Установка на новом компьютере:

```sh
git clone https://github.com/assa99g/message-hub.git
cd message-hub
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

4. Подготовить OAuth-клиент типа Desktop app и загрузить его JSON в локальный Message Hub. Пароли, коды и токены в чат или репозиторий не помещать. При необходимости принятия условий или предоставления чувствительных прав следовать действующим правилам подтверждения инструментов.
5. Пользователь по очереди проходит Google-вход для каждого нужного ящика. После этого проверить получение новых писем, изоляцию ящиков, повторный сбор без дублей и сохранение после перезапуска. Старую переписку не загружать.
6. Только после работоспособного Gmail переходить к Telegram, аналитике и следующей функциональности. Конкретный следующий шаг можно скорректировать по указанию пользователя.
