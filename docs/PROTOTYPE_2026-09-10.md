# Message Hub — прототип экранов

Дата: 10 сентября 2026 года. Версия: день 2.

## Как посмотреть

Открыть [index.html](../prototype/dist/index.html) в браузере или запустить локальный сервер по инструкции в [README](../README.md).

Прототип сохраняется в Git как обычные HTML, CSS и JavaScript без внешних библиотек, шрифтов, аналитики и сетевых вызовов. Все данные вымышлены, дата зафиксирована. Изменения существуют только до перезагрузки страницы. Настройки можно отдельно выгрузить в JSON.

## Карта экранов

| Экран | Что показывает | Что можно попробовать |
| --- | --- | --- |
| Сегодня | Счётчики, срочное, просроченное, предложения задач и план | Открыть сообщение, утвердить время, перейти к уточнению. |
| Входящие | 8 примеров из 6 типов источников | Поиск, фильтры, открытие полного текста, изменение важности и сферы. |
| Задачи | Предложенные, утверждённые, просроченные и завершённые задачи | Утвердить, изменить время, отложить, отклонить, завершить, указать причину невыполнения. |
| Календарь | Рабочая неделя 7–11 сентября | Увидеть утверждённые задачи; изменить время. |
| Уточнения | Неоднозначная фраза о договоре | Создать предложение задачи или оставить информацию. |
| Источники | Карточки будущих подключений и пример неиспользуемого канала | Оставить канал, исключить из обработки с подтверждением, вернуть его. |
| Настройки | Интервалы, пороги, тихие часы, резерв, сферы | Изменить параметры, добавить или удалить сферу, выгрузить настройки. |

## Сценарии для обсуждения

1. **Письмо → задача → календарь.** На «Сегодня» открыть письмо о смете: оно станет прочитанным. У задачи «Согласовать две позиции в смете» открыть источники: видны два письма, объединённые в одно поручение. Нажать «Утвердить время» и перейти в календарь — задача появится в четверг.
2. **Невыполненная задача.** В задачах найти «Подготовить вопросы к встрече», выбрать «Не сделана», указать причину или свой текст. Следующий шаг предлагает время и длительность; кнопка подтверждает перенос. При причине «Задача сложнее ожидаемого» исходная длительность предложения увеличивается вдвое.
3. **Неоднозначное сообщение.** В «Уточнениях» решить, нужна ли проверка договора. При выборе «Да» появляется только предложение — календарь пока не меняется.
4. **Пересмотр источника.** На экране источников исключить демонстрационный канал: появится подтверждение, затем возможность вернуть его. Внешняя подписка не изменяется.
5. **Настройки.** Изменить частоту проверки и сохранить. Карточки источников покажут выбранный интервал. Добавить сферу и выбрать её у сообщения. После удаления сферы материалы сохраняются «Без категории».

## Границы прототипа

- Не подключает реальные аккаунты, не собирает сообщения и не отправляет текст в ИИ.
- Не создаёт события в Google/Apple Calendar; не проверяет реальную занятость.
- Не рассчитывает конфликты, дорогу, перерывы и оптимальный план. Время и оценки — демонстрационные предложения. Для изменения времени доступны 10 и 11 сентября внутри показанной недели.
- Варианты причин невыполнения и ручной перенос работают; адаптивное планирование по накопленным причинам ещё не реализовано.
- Настройка автозапуска не меняет macOS. Выгрузка JSON не является резервной копией будущей системы.
- Не показывает настоящую историю чтения в сторонних приложениях. Источник без активности — отдельный вымышленный пример будущего состояния.
- Карточка редактирования сообщения позволяет выбрать одну сферу; несколько сфер, переименование групп и правила отправителей остаются требованиями полной версии.
- Предусмотрены необязательные WebMCP-инструменты чтения и утверждения демонстрационной задачи, если браузер поддерживает API. Без него интерфейс работает обычным образом. Проверка в настоящем WebMCP-контексте не выполнялась.

## Проверки

Перед сохранением проверяются синтаксис JavaScript, наличие локальных ресурсов, отображение семи представлений в изолированной проверке состояния и переход предложенной задачи в утверждённую. Это не заменяет визуальное тестирование в браузере; оно в этой итерации не запрашивалось.

## Следующая реализация

После просмотра экранов — внести правки интерфейса, проверить доступность подключений, затем реализовать хранение, рабочие интеграции и установку для отдельного пользователя macOS. Публичная публикация сайта не требуется: прототип рассчитан на локальную работу, как согласовано.
