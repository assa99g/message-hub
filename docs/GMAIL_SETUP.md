# Gmail: подключение нескольких ящиков

## Состояние на 11 сентября 2026 года

Подготовлена локальная версия: OAuth-вход через Google, несколько аккаунтов, SQLite, сбор только новых входящих писем, общий список с фильтром по ящику, текстовый просмотр и события открытий для статистики. Дизайн использует существующие стили и навигацию. Исходный демонстрационный прототип сохранён отдельно.

Реальное подключение пока не проверено: нужен OAuth-клиент пользователя и отдельный вход в каждый ящик. Тесты используют вымышленные данные и не обращаются к Gmail. Автозапуск, автоматические резервные копии, экспорт для переноса, ИИ и календари ещё не реализованы.

## Локальный запуск

Использовать Python 3.12 или новее. Для разработки создано отдельное окружение `.venv` на Python 3.12; системный Python macOS 3.9 с LibreSSL для подключения Google не используется.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m message_hub.server
```

Программа открывает браузер с ключом локальной сессии. После перезапуска использовать новую ссылку из запуска: прежний ключ больше не действует. Сервер слушает только `127.0.0.1`, API требует ключ сессии. OAuth-вход открывается в обычном системном браузере, а не внутри встроенного браузера приложения.

По умолчанию рабочие данные находятся в `~/Library/Application Support/Message Hub` текущего пользователя macOS. Разрешения файлов ограничены текущим пользователем; ключи доступа Gmail сохраняются в его Связке ключей macOS. База SQLite сама по себе не зашифрована. Для разработки используется отдельный каталог:

```sh
.venv/bin/python -m message_hub.server --data-dir .local-data
```

Интервал проверки задаётся при запуске, например `--interval 30`; по умолчанию 60 минут. При остановке или сне сбор приостанавливается. После запуска и очередного пробуждения сбор догружает доступные новые сообщения. Изменение интервала через интерфейс будет добавлено позднее.

## Однократная настройка Google

1. Открыть [Google Cloud Console](https://console.cloud.google.com/) под аккаунтом владельца приложения и создать проект Message Hub либо использовать предназначенный для него существующий проект.
2. Включить Gmail API для выбранного проекта.
3. Настроить Google Auth Platform: название Message Hub, адрес поддержки и контактный адрес разработчика.
4. Для личных Gmail-аккаунтов выбрать аудиторию External. Пока приложение находится в Testing, добавить все подключаемые адреса в Test users.
5. В Data Access добавить только `https://www.googleapis.com/auth/gmail.readonly`.
6. Создать OAuth client типа **Desktop app**, скачать его JSON.
7. В Message Hub → «Источники» выбрать этот файл. Файл сохранится локально в подкаталоге `secrets`, не в базе и не в Git.
8. Нажать «Добавить Gmail-ящик», пройти вход в Google, разрешить чтение. Затем повторить для следующего ящика. После подключения нажать «Проверить почту».

Нужен один OAuth-клиент для приложения, отдельный клиент для каждого ящика не требуется. В режиме Testing Google выдаёт разрешение с refresh token на 7 дней для Gmail; затем понадобится повторный вход. Перед повседневным использованием нужно отдельно завершить настройку статуса приложения с учётом требований Google. Корпоративный Google Workspace может ограничивать доступ политикой администратора.

## Поведение сбора

- Дата начала фиксируется отдельно для каждого успешно подключённого аккаунта. Повторная авторизация того же адреса сохраняет первоначальную дату, письма и позицию сбора.
- Сбор охватывает доступные новые входящие сообщения, включая архив, спам и корзину. Отправленные и черновики исключаются.
- История Gmail используется для догрузки. Если она истекла, выполняется поиск доступных писем с даты подключения, с точной проверкой времени и защитой от дублей.
- Письма, окончательно удалённые до сбора, получить невозможно. Импорт в Gmail со старой внутренней датой также не считается новым письмом в этой версии.
- Текст и HTML-преобразование поддерживаются; вложения и внешние изображения не загружаются. Письма без встроенного доступного текста отображаются с соответствующим пояснением.
- Ошибка одного ящика не останавливает проверку других. При ошибке позиция сбора не сдвигается; повторная попытка безопасна для уже сохранённых писем.
- Открытия в Message Hub фиксируются отдельно от прочтения в Gmail. Счётчик открытых писем считает уникальные письма; журнал хранит каждое открытие.
- Секреты и тексты не отправляются сервисам ИИ. OAuth и запросы к Gmail используют Google; программа не отправляет, не удаляет и не помечает письма прочитанными в Gmail.
- Смена папки данных создаёт отдельное пространство с собственной базой и отдельными записями Связки ключей. Для переноса потребуется перенос базы и повторная авторизация; автоматический перенос пока не реализован.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

12 проверок: граница первого сбора, дубли и несколько аккаунтов, сохранение позиции после сбоя, истёкшая история и пагинация, удалённые письма, повторная авторизация, извлечение текста без вложений, статистика открытий, независимость ящиков, настройки клиента, защита локального API. Проверен также интерфейс пустого хранилища в браузере.
